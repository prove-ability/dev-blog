[지난 편](/posts/homepage-brand-alignment/)에서는 인스타그램과 홈페이지의 인상을 맞췄다. 기존 로고와 움직이는 첫 화면을 살리고, 새싹은 문의 버튼 옆에 두는 것으로 정리했다. 화면을 확인한 뒤에는 검색으로 들어오는 길도 살펴보고 싶어졌다.

Google Search Console에 로그인해 SEO 상태를 확인해 달라고 요청했다. 그 과정에서 예전 블로그 주소 일부가 404로 잡혀 있는 것을 발견했다. 디자인을 바꿨다고 해서 방문자가 원하는 글에 도착하는 것까지 보장되지는 않았다.

이번 글은 **「유스핀랩 브랜딩과 운영을 만들어가는 기록」의 세 번째 편**이다. 여기서 다루는 블로그는 지금 이 개발 블로그가 아니라, 유스핀랩 홈페이지의 `/blog` 영역이다. 나는 기존 주소 유지와 404 복구를 먼저 진행하도록 범위를 정하고 병합·배포, GSC 후속 확인을 승인했다. 원인 분석과 코드 수정, 검사와 브라우저 확인은 AI가 진행했다.

## 글은 남아 있는데 홈페이지에서는 찾을 수 없었다

당시 홈페이지는 네이버 블로그의 RSS를 이용해 글을 보여주고 있었다. 문제는 그 최근 목록이 상세 페이지에서 글을 찾는 기준이기도 했다는 점이었다. RSS에서 오래된 글이 빠지면 홈페이지에서도 그 주소에 해당하는 글을 찾지 못했다. 네이버 원문은 공개되어 있는데 홈페이지 주소는 사라지는 상황이었다.

2026년 11월 16일 확인한 GSC의 404 대상은 7개였다. 공개 원문을 대조하면서, 별도로 확인했던 미색인 글 1개도 함께 복구 대상으로 넣었다. **404 7개와 미색인 1개는 같은 분류가 아니었다.** 원래의 문제와 복구 범위를 섞어 쓰지 않으려고 이 둘은 구분해 두었다.

단순히 사이트맵을 다시 제출하는 것으로 끝낼 수는 없었다. 새 글이 쌓여 RSS 목록이 바뀌면 같은 문제가 다시 생길 구조였기 때문이다.

## 최근 목록과 공개된 주소의 수명을 분리했다

바꾼 방식은 비교적 단순했다. 글 데이터를 저장소의 JSON 파일에 보관하고, 목록 API와 상세 페이지, 사이트맵이 모두 그 데이터를 읽도록 했다. RSS는 새 글을 발견하는 용도로 남겼다.

이미 서비스하던 50개 글에 공개 원문을 확인한 8개를 더해, 작업 당시 58개를 보관했다. 복구한 글은 원문의 제목·날짜와 본문 발췌를 사용했다. AI가 없어진 본문을 추측해서 채운 것은 아니다. 전체 내용은 기존처럼 ‘네이버 블로그에서 전체 글 보기’ 링크로 연결했다.

이렇게 하면 RSS가 잠시 응답하지 않거나 예전 글이 최근 목록에서 빠져도, 이미 공개한 홈페이지 주소를 계속 찾을 수 있다. 글이 노출되는 곳마다 서로 다른 목록을 읽지 않게 된 것도 중요한 변화였다.

![RSS에서 새 글을 수집하고 검토 PR을 거쳐 보관한 뒤, 목록과 상세 페이지 및 사이트맵에 반영하는 흐름](/images/blog-url-recovery/archive-flow.svg)

RSS는 수집의 출발점이고, 홈페이지가 읽는 기준은 검토 후 보관한 데이터다. 새 글은 PR 병합과 배포를 거쳐야 공개된다. [Mermaid 원본](/images/blog-url-recovery/archive-flow.mmd)도 함께 남겼다.

주소를 보관할 때는 제목만 비교하지 않았다. 네이버 원문의 게시물 ID로 같은 글인지 판단하고, 이미 보관한 글이면 기존 주소를 유지한다. 원문 제목이 바뀌었다고 홈페이지 주소까지 새로 만들지 않는다. 새 글의 제목이 기존 글과 같아 주소가 겹치는 경우에는 원문 ID를 붙여 구분했다.

대신 운영상 감수할 부분도 생겼다. 원문의 수정·삭제를 자동으로 따라가지 않으므로, 정정하거나 내려야 하는 글은 보관 데이터도 따로 검토해야 한다. 주소를 오래 유지하는 것과 원문 상태를 실시간으로 복제하는 것은 같은 일이 아니었다.

## 복구할 주소와 정말 없는 주소를 구분했다

기존 주소를 살린다고 모든 요청에 정상 페이지를 반환한 것은 아니다. 보관한 글은 원래 주소에서 다시 열리게 하고, 존재하지 않는 주소는 HTTP 404와 `noindex`를 반환하도록 했다. 별도의 `/404` 주소로 보내는 방식도 정리했다.

검사에서는 화면에 ‘없음’이 보이는지만 확인하지 않았다. 복구한 8개 주소가 HTTP 200으로 응답하는지, 각 글의 대표 주소인 canonical이 자기 주소를 가리키는지, 없는 주소는 실제로 404를 반환하는지 확인했다. 한글 주소 조회도 검사 대상에 넣었다.

수정 당시 회귀 검사 9개, 린트, 타입 검사와 프로덕션 빌드를 통과했다. 사이트맵에는 기본 페이지 7개와 글 58개, 총 65개 URL이 들어갔다. 이 숫자는 복구 시점의 구성이지, 앞으로 유지해야 할 글 수의 목표는 아니다.

## 새 글은 자동으로 수집하고, 노출은 검토 뒤에

데이터를 파일로 보관하면 새 글을 계속 추가하는 방법도 필요했다. 매일 한국시간 오전 8시 17분에 실행하도록 GitHub Actions를 설정하고, 새 글이 있을 때 검토 PR을 만드는 흐름을 붙였다. 예약 실행은 지연될 수 있으며, 자동 병합은 하지 않는다.

저장소의 자동 PR 생성 설정도 확인했다. 해당 설정이 꺼져 있어 활성화를 승인했고, 이후 수동 실행으로 수집과 검사가 성공하는 것까지 확인했다. 당시에는 58개에서 58개로 변화가 없어 새 PR이 생성되지는 않았다. 따라서 이 실행을 ‘새 글 PR 생성까지 실제로 검증했다’고 표현할 수는 없다.

결과적으로 네이버에 새 글을 올리자마자 홈페이지에 나타나는 구조는 아니다. 수집된 변경을 검토하고 병합·배포해야 노출된다. 공개된 주소를 먼저 보관해 두겠다는 선택에는 이 운영 절차도 따라왔다.

## 배포 완료와 GSC 확인 완료는 달랐다

수정을 병합하고 공개 배포한 뒤, 사이트맵을 다시 제출하고 GSC의 404 수정 확인을 요청했다. 사이트에서 글이 열리는지 확인하는 단계와 Google이 다시 방문해 결과를 갱신하는 단계는 따로 남겨 두었다.

![2026년 11월 16일 GSC에서 404 문제의 유효성 검사 상태가 시작됨으로 표시된 화면](/images/blog-url-recovery/gsc-validation-started.png)

2026년 11월 16일 작업 당시 캡처다. 계정 영역은 제외했다. 화면의 ‘시작됨’은 재검증 요청을 접수한 상태이며, 복구 완료나 색인 완료를 뜻하지 않는다.

![GSC에서 사이트맵이 제출됐음을 알리는 확인 메시지](/images/blog-url-recovery/gsc-sitemap-submitted.png)

같은 날 확인한 사이트맵 제출 결과다. 이 메시지만으로 모든 URL의 색인이나 검색 노출이 보장되는 것은 아니다.

11월 18일에 다시 확인했을 때는 Google이 사이트맵의 URL 65개를 읽었고 오류와 경고는 모두 0개였다. 다만 404 유효성 검사는 여전히 ‘시작됨’이었고, 상세 화면에는 접수중 7개와 실패 0개가 표시됐다. 개별 URL 검사도 수정 전 크롤링 기록을 보여줬다. 위 캡처는 11월 16일 당시 화면으로 그대로 남겼다.

## 이번에 확인한 결과

이번 작업의 결과는 검색 순위보다 사이트가 실제로 어떻게 동작하는지로 정리할 수 있었다.

| 확인한 항목 | 작업 후 확인한 상태 |
| --- | --- |
| 끊어진 주소 | 기존 404 대상 7개 주소를 복구해 HTTP 200 응답 확인 |
| 글 보관 | 기존 글과 복구 글을 합쳐 58개 보관. RSS 목록에서 빠져도 기존 주소 유지 |
| 사이트맵 | Google이 URL 65개를 읽었고 오류·경고 0개 확인 |
| 회귀 검사 | RSS 목록 순환·제목 변경·주소 조회 등을 포함한 검사 9개와 프로덕션 빌드 통과 |

사이트맵 수치는 11월 18일 GSC 조회 결과이고, 주소 복구와 빌드 검증은 11월 16일 작업 기록을 기준으로 했다. **이 결과가 검색 유입 증가나 색인 완료를 뜻하지는 않는다.** Google 재검증 통과 여부와 검색 노출·클릭 변화는 이후 데이터가 쌓이면 확인 기간과 함께 후속 기록으로 추가하려고 한다. 지금은 그 성과를 미리 적지 않았다.

## 브랜딩을 맞춘 다음에는, 찾아오는 길을 유지하기

처음에는 색상과 캐릭터를 맞추는 작업이었다. 그런데 홈페이지를 점검하다 보니, 예전에 공유한 링크로 들어온 사람이 실제 글을 읽을 수 있는지도 함께 챙겨야 했다. 수업 후기나 교육 활동 글은 브랜드를 이해하는 자료인데, 주소가 끊기면 그 내용을 보기 전에 방문이 끝난다.

검색 유입이 늘었는지는 아직 확인하지 못했다. 다만 끊어졌던 주소를 복구하고, RSS 목록이 바뀌어도 기존 글이 사라지지 않도록 구조를 바꿨다. 사이트맵은 정상 처리됐고, Google의 재검증 결과는 기다리고 있다. 다음에는 검색 데이터의 변화와 실제 새 글의 검토 PR부터 배포까지 이어지는 흐름을 확인할 차례다.
